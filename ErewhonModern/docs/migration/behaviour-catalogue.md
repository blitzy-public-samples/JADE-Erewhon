# Behaviour catalogue

This catalogue is the frozen contract that every port and every test of ErewhonModern follows. Each entry names the JADE source that confirms the rule, the inputs and the expected outcome (a message key with its locale-5129 English text, a status code or a returned value), the target component and the test that proves it. JADE test names are ported unchanged. `B##_*` tests live in `tests/Erewhon.Application.Tests/Catalogue/BehaviourCatalogueTests.cs`, except the REST ones, which live in `tests/Erewhon.Api.Tests/Rest/RestCatalogueTests.cs`, and the SOAP ones, which live in `tests/Erewhon.Soap.Tests/SoapCatalogueTests.cs`. Paths are relative to `ErewhonModern/`. The reasons for each decision are in `docs/migration/decision-log.md`, cited here by D-ID.

## Machine-read format

`TraceabilityCoverageTests` reads this file. The format is fixed by D-48:

- Every table whose first header cell is `ID` and whose IDs match `^(B|T|C|Q|EE)-\d{2}$` is a catalogue table. All other tables in this file start with a different header cell.
- One table row per line. A line break inside a cell is written `<br>`, never a raw newline. A `|` inside a cell is escaped as `\|`.
- IDs are zero-padded (`B-01`, `T-01`, `C-01`, `Q-01`, `EE-01`), and the first cell holds only the ID.
- Columns per table kind:
  - B tables: `| ID | Rule (confirming source) | Inputs → expected outcome | Target component | Proving test |`
  - T table: `| ID | Original tests and fixture | Asserted values beyond the named entries | Rules | Proving test |`
  - C table: `| ID | Request states | Source shows (citation) | Decision |`; the Decision cell starts with its D-ID.
  - Q table: `| ID | Quirk (source) | Proving test |`
  - EE table: `| ID | JADE behaviour | Why it cannot be matched or tested | What was done instead |`
- Sources are cited `[Erewhon/<file>:<locator>]`, one file per bracket: `<file>` is the file's path below `Erewhon/`, and `<locator>` is either one or more line spans separated by `, `, each `L<n>` or `L<n>-<m>` with 1 ≤ n ≤ m ≤ the file's line count, or the name of a section of that file (for example `[Erewhon/ErewhonModelSchema.scm:L11804]`, `[Erewhon/ErewhonModelSchema.scm:L6423, L6573-6609]` and `[Erewhon/ErewhonModelSchema.scm:memberKeyDefinitions]`).
- Test tokens are backticked, one token per test: an xUnit test as `Class.method`, or `Class.*` for every method of that class; catalogue tests always with their class (`BehaviourCatalogueTests.B07_ItemPriceZeroIsRejected`, `RestCatalogueTests.B60_RestDuplicateAgentIs400`, `SoapCatalogueTests.B51_ErrorUnauthorizedIs403`); a React or Playwright test as its file path (`web/src/shop/ShopPage.test.tsx`, `web/e2e/checkout.spec.ts`). A JADE original that has no target test is written in JADE notation, `Class::method`.
- Target component cells hold backticked paths, for example `src/Erewhon.Application/Services/ItemService.cs`.
- Messages are written as the key with its `$` prefix followed by the verbatim locale-5129 text in double quotes. A parameter appears as `\<name\>` at its position. `CrLf` in the source is written `\r\n`, and a line break inside a source literal is written `\n`. Runs of spaces are kept as they occur in the source.

## Selection rule

The catalogue holds three kinds of content, with equivalent cases grouped into one entry:

- every reachable, non-boilerplate branch of a method that the legacy-disposition rule (D-34) carries over: each validation outcome, returned value, ordering and state change. Boilerplate (plain field getters and setters, `create`/`delete` constructors and `foreach` plumbing) is excluded;
- every assertion of the 214 accounted-for JADE `unitTest` methods (127 model, 24 view, 38 REST, 25 SOAP);
- every REST, SOAP, form and cross-cutting rule the request lists.

`B-` entries state rules. The `T-` table states, per original test class, the fixture and every asserted value that the `B-` entries it names do not already state. `C-` entries list where the source contradicts the request or does not confirm it; the source governs. `Q-` entries list JADE quirks that are reproduced, never fixed. `EE-` entries list equivalence exceptions.

- All 289 keys live in `src/Erewhon.Application/Messages/messages.en-NZ.json`: 273 from the locale-5129 `translatableStringDefinitions` of [Erewhon/ErewhonModelSchema.scm:L2624-2921] and 16 from [Erewhon/ErewhonBaseSchema.scm:L34-72].

### Null semantics

JADE treats a zero `Integer`/`Decimal`, an empty `String` and a day-0 `Date` as `null`, and `isValid` is false for a null date (D-17). The ported methods rely on it at these sites:

- `price = null` rejects a price of 0 [Erewhon/ErewhonModelSchema.scm:L11804];
- `salePrice = null` rejects a sale price of 0, confirmed by `TestRetailSale.testInvalidPrice`, which sets 0 and expects `$RetailSalePriceRequired` [Erewhon/ErewhonModelSchema.scm:L12990, L19893-19943];
- `codeNumber = null` triggers allocation for 0 [Erewhon/ErewhonModelSchema.scm:L11727];
- `priceLow <> null` treats a search bound of 0 as no bound [Erewhon/ErewhonModelSchema.scm:L14350-14479].

Every `= null` test in a ported method goes through `JadeValues.IsNull`. B-07, B-21, B-35 and Q-25 pin the consequences; C-03 and C-04 record where the request disagrees.

### Field lengths

Each `String[n]` attribute is a `varchar(n)` column. `FieldLengths.Check` (`src/Erewhon.Application/Common/FieldLengths.cs`) raises `StringTooLongException`, JADE error 1035 "String too long", at the boundary where JADE first assigns the value to a bounded attribute and before any trimming that follows that assignment (D-41, B-22):

- **Bounded `DTO*` fields (REST and SOAP).** JADE deserialises a `DTO*` parameter into its fixed-width fields [Erewhon/ErehwhonExternalInterfacesSchema.scm:L107-147] before the operation runs, and the provider copies them untrimmed into the TA [Erewhon/ErehwhonExternalInterfacesSchema.scm:L2652-2691]. REST `postCreateAgent`, `postCreateClient` and SOAP `updateAgentWithDTO`, `updateClientWithDTO` therefore check those fields on entry, before any branch: REST answers 500 with an empty body through `RestExceptionFilter`; SOAP answers a fault carrying "String too long (1035)" (EE-17).
- **Scalar parameters.** Scalar `String` parameters are unbounded (e.g. REST `getAgent(pName : String)` [Erewhon/ErehwhonExternalInterfacesSchema.scm:L2328-2355]). Each is checked only where the operation assigns it to a bounded attribute, after every branch that precedes the assignment. SOAP `updateAgent` returns 404 for an unknown agent before it assigns its address parameters [Erewhon/ErehwhonExternalInterfacesSchema.scm:L6700-6745]; a lookup by an overlong name is an ordinary miss.
- **Application services.** The TA attributes have the model lengths and are assigned before `doPreValidate` trims [Erewhon/ErewhonModelSchema.scm:L11738-11739]; each service checks its command values on entry, before `PreValidate`.
- **React forms.** Where a JADE form trims a text before assigning it to the TA, the React screen trims before sending.
- **Seed loader.** `getNextToken` trims each token before assignment [Erewhon/ErewhonModelSchema.scm:L7982-8051], so the loader checks trimmed tokens.

## Seed data

`src/Erewhon.Persistence/Seed/InitialDataLoader.cs` ports `InitialDataLoader.loadData` [Erewhon/ErewhonModelSchema.scm:L8427-8509] step for step:

1. **Directory.** `validateDirectoryPath` trims the path, appends a separator when missing, and raises `Ex_500004_Invalid_directory_path` for an empty, invalid or unavailable path [Erewhon/ErewhonModelSchema.scm:L8928-8975].
2. **Purge.** Delete `Company.firstInstance()` (cascade) and commit that purge in its own transaction (Q-18).
3. **Company.** In a second transaction, create the company "Erewhon Investments Inc" (`$CompanyName`) with the address `$CompanyAddress1` "Erewhon House", `$CompanyAddress2` "Christchurch", `$CompanyAddress3` "New Zealand", `$CompanyEMail` "discover@jadeworld.com", `$CompanyFax` "(64) 3 555 1267", `$CompanyPhone` "(64) 3 555 4519", `$CompanyWebSite` "www.jadeworld.com" [Erewhon/ErewhonModelSchema.scm:L7913-7957]. `Ex_500003_Company_already_exists` is raised only if a company survived the purge (B-80, D-43).
4. **Date offset.** `dateOffset` = current date − 1 January 2000, in days.
5. **Load order.** Locations, agents, clients, categories, retail items, tender items, category rates, agent rates, tenders, retail sales; then commit.
6. **Validation path.** Every record goes through its application service in Ambient mode (`persistEntityInTransState`), the production validation path. The result is ignored. The agent-rate, category-rate, retail-item, retail-sale, tender-item and tender loaders count every line that step 7 does not skip, persisted or not (Q-20) [Erewhon/ErewhonModelSchema.scm:L8152, L8344, L8665, L8741, L8836, L8913]. The agents and clients loaders report the size of the company's agent and client collections (`allAgents.size`, `allClients.size`) [Erewhon/ErewhonModelSchema.scm:L8230, L8423]; the locations loader reports `getNumberOfLocations`, the number of the company's countries plus their regions [Erewhon/ErewhonModelSchema.scm:L8583, L6786-6792]; and the categories loader reports `allAgents.size`, the agent count (Q-19) [Erewhon/ErewhonModelSchema.scm:L8288] (D-58).
7. **Reading lines.** Each line is `trimBlanks`; empty lines and lines starting with `#` are skipped. `getNextToken` skips leading tabs and spaces, returns the text up to the next tab trimmed with `trimBlanks`, and returns null for a literal `null` token [Erewhon/ErewhonModelSchema.scm:L7982-8051].
8. **Records.** Agent and client address tokens are read in the order street, city, country, email, fax, phone, web site. Item GUIDs come from the files. Each item draws its code number through the allocator before validation (`getNextCodeNumber`). Each item's photo is loaded from `<dir>/<file>`. An agent rate attaches the agent to the category rate with the named percentage (`addOrRemoveAgents`, B-15). A retail sale names its item by `allRetailItems[guid]`, a tender by `allTenderItems[guid]` [Erewhon/ErewhonModelSchema.scm:L8086-8927].
9. **Date shift.** Listed and closure dates, sale timestamps and tender timestamps are shifted by `dateOffset`; times are kept.
10. **Console output.** The loader writes `$Loading` per file, `$LoadedObject` per record (`$Loading` per agent), the per-file `*Loaded*` lines, including `$CategoriesLoadedInMS` with the agent count (Q-19), `$ClosingTendersSever` "Closing Tenders (Server Method)", and finally `$DatabaseInitialized` (EE-11).
11. **Post-load closure.** After the commit the loader closes tenders at the current date and writes `$TenderSalesBuilt` "\<pQty\> Tender Sales built in \<pDuration\>" or `$NoTendersToCloseAsAt` "No Tenders to close as at \<pDate\>" [Erewhon/ErewhonModelSchema.scm:L7892-7911].

The loader has two triggers: the CLI verb `seed <dataDir>`, which replaces the `DataLoader` application, and `POST /api/app/setup/load-data`, which replaces the logon-time folder browse with the configured `Erewhon:Seed:DataDirectory` and is refused once a company exists (D-18, D-43).
